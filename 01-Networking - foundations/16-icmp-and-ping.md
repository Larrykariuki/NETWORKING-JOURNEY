## ICMP and Ping
ICMP: Stands for internet control message protocol and is used by network devices to send messages and report network problems for instance when a router cant deliver a packet to its destination then the router sends an ICMP message  to explain the error that occurred, it is not a transport protocal like TCP and UDP and it works the  IP on a network, Ping: Is a tool used in troubleshooting networks and uses the ICMP echo requests  and echo replies messages to test wether a destination responds over an IP network for example on a linux terminal, i can run ping -c 5 8.8.8.8 which means this sends 5 ping requests to the IP address 8.8.8.8 then stops. The option -c tells the terminal of linux to send 5 requests
## How Ping works
My laptop sends an ICMP echo request then if it permits a reply it sends the ICMP echo reply and my laptop measures the time it took to receive the reply, a successful reply shows that the destination is reachable using that particular network path but then a ping that is successful does not necessarily mean that every service or application on the destination is working 
## Understanding the results of requests
A successful reply may look like 64 bytes from 8.8.8.8, icmp-seq=1 ttl=17 time=20.7ms, this means that the 64 bytes is the size of the reply, 8.8.8.8 is the IP address responding icmp-seq=1 is the sequence number of the reply time = 20.7 ms is the measured time (round-trip), Round trip time is what measures how long the request and the reply was and is not the same as the bandwidth
## Request Timed out
A timeout request means that no reply received to the destination within the waiting period and causes may include the destination is offline, the network connection or the route has failed , the firewall has filtered ICMP messages, the destination does not respond to ping or the request and reply was lost but also note that a ping does not automatically mean that the destination is offline there might be other cases
## Packet loss
If lets say i send 4 requests and receive only 3 replies then that means the packet loss is 25 percent and may indicate congestion, ana unreliable network connection, filtering or other network problems and needs more tests to identify the cause
## Comparison of ICMP,TCP and UDP
ICMP: Carries network control and diagnostic messages, TCP provides relaible and ordered data travelling between applications while UDP sends datagrams without TCP capabilities of delivery and guaranteed order, it does not use the TCP or UDP port number and has its own inbuilt messages and codes 
## What is TTL
TTL stands for time to live, routers reduce the ttl values as a packet travels through a network, if it reaches 0 then the packet is discarded  and this helps prevent packets from circulating forever in a loop
## Using Ping while troubleshooting
I can use ping to test different points in a network for instance 127.0.0.1: this tests the local network loopback interface, 192.168.1.1: test my home router if that is its IP address, 8.8.8.8: tests if the public IP address is reachable through the DNS, google.com: tests the name resolution and then attempts to reach an address returned for that name. If an IP address responds but a domain name doesnt, then the DNS resolution may be the problem, but then one should check other causes before coming to a conclusion and that is trouble shooting
## ICMP and Cybersecurity
In cybersecurity the ICMP is very useful for both defenders and security testers, in defenders they use the ICMP information to troubleshoot connectivity problems, investigate packet loss and latency, identify routing problems and monitoring unusual network traffic, attackers can use ping sweeps to discover which of the IP address respond and they can also abuse the ICMP traffic to overwhelm a target While defenders can monitor suspicious patterns and apply the appropriate network controls. Blocking all ICMP is not a good security practice because in some cases the ICMP messages can be useful or important for troubleshooting and the day to day network operations, one should only test systems owned or have been granted permision to access
